# kclaw 上手教程

从零开始把 kclaw 用起来：安装、第一次对话、会话、记忆、定时任务、WebUI。跟完大约 15 分钟。

> kclaw 是一个本地运行的个人 agent。它在后台跑一个 daemon（守护进程，负责保管全部状态），终端 CLI 和浏览器 WebUI 都是连着它的客户端。本教程只需要用 CLI 和 WebUI：daemon 会在需要时自动启动，不用单独管它。

## 1. 准备

- **Node >= 22**：终端里执行 `node -v`，主版本号要不低于 22。kclaw 启动时也会检查，版本太低会打印一行提示然后退出。
- **一个模型的访问方式**，二选一：
  - **在线 API key（以 DeepSeek 为例）**：在 DeepSeek 开放平台注册并创建一个 API key（`sk-` 开头的一串字符）。
  - **本地 Ollama**：不想用云服务的话，先[安装 Ollama](https://ollama.com) 并保持它在运行，再下载一个模型，例如 `ollama pull qwen2.5`。不需要任何 key。

## 2. 安装与第一次启动

```bash
npm i -g kclaw
kclaw chat
```

如果还没有任何模型配置，而且你是在正常的终端里运行，`kclaw chat` 会进入一个 30 秒左右的配置向导。它只做一件事：把模型配置写进 `~/.kclaw/config.yaml`，写好后以后不再出现。

### 路线一：DeepSeek 模板（贴 key）

1. **选模板**：用上下方向键选中 `DeepSeek`，回车。
2. **输入 API key**：粘贴你的 key。输入不会回显（屏幕上看不到字符），粘贴完直接回车即可。
3. **输入模型名**：直接回车，使用默认的 `deepseek-chat`。
4. **连通测试**：kclaw 会发一个只消耗 1 个 token 的最小请求，验证 key、模型名、接口地址三样都能用。通过后写入配置文件（权限设为仅本用户可读写），然后自动进入对话。

### 路线二：Ollama（零 key）

选模板 `Ollama (local)`：接口地址已预填本机的 `http://127.0.0.1:11434/v1`，key 这一步直接跳过，只需输入模型名——填你前面 `ollama pull` 下载的那个名字（不确定就先跑 `ollama list` 看看），其余步骤相同。

### 向导失败了怎么办

连通测试失败时，kclaw 会把错误归成三类，用一句人话告诉你，并问是否重试；重试会直接回到出错的那一步：

| 提示 | 含义 | 检查什么 |
|------|------|---------|
| API key 无效（401/403） | key 错了或失效了 | 重新复制粘贴一次 key |
| 模型名不对（404/400） | 服务端不认识这个模型名 | Ollama 用 `ollama list` 核对；DeepSeek 回车用默认 |
| 连不上服务端 | 请求根本没送达 | 网络是否可用、接口地址是否正确（Ollama 要先启动） |

选「否」或按 Ctrl+C 都会干净退出，不写任何文件；下次 `kclaw chat` 会重新进入向导。

不想走向导也可以：手写 `~/.kclaw/config.yaml`，或设置 `KCLAW_LLM_BASE_URL / KCLAW_LLM_API_KEY / KCLAW_LLM_MODEL` 环境变量，格式见 [README](../README.zh-CN.md) 的「配置要点」一节。

## 3. 第一轮对话

进入 REPL（read-eval-print loop：读一行输入、处理、打印结果、再等下一行的交互循环）后，直接打字发送：

```text
你好，用一句话介绍你能做什么
```

回复会以流式方式逐字打印出来。

### 让它动手干活

问一个必须执行命令才能回答的问题：

```text
~/Downloads 里最大的文件是哪个？
```

agent 会调用 exec 工具去执行命令。exec 属于高危工具，执行前你会看到一张**确认卡片**，列出工具名、参数和风险等级，问你允许还是拒绝：

- 选**允许**：命令执行，agent 拿到输出后继续回答你。
- 选**拒绝**：agent 收到「用户拒绝」，会改用别的方式回应（比如告诉你它没法查）。

每一次允许或拒绝都会记进审计日志，之后可以在 WebUI 的「审计」页查到。确认卡片有时限（默认 120 秒），超时按拒绝处理。回复进行中按 Ctrl+C 可以取消当前这一轮。

## 4. 会话管理

REPL 里用 `/` 开头的命令管理会话：

| 命令 | 作用 |
|------|------|
| `/new 采购清单` | 开一个带标题的新会话 |
| `/clear` | 快速开一个不带标题的干净会话 |
| `/sessions` | 列出全部会话，方向键选中一个回车即切换过去 |
| `/help` | 列出所有可用命令（输错命令时会提示你来看它） |
| `/exit` | 退出 REPL |

不手动指定标题也行：新会话默认叫「新会话」，你发出第一条消息后，kclaw 会根据消息内容自动生成一个标题（不超过 30 字）；手动改过的标题不会被覆盖。

历史不会丢：每条消息都写进了 `~/.kclaw/sessions/<会话id>/messages.jsonl`。想接着上次的聊，用 `kclaw chat --session <id>` 恢复指定会话，或进 REPL 后 `/sessions` 挑一个。

## 5. 记忆

让 agent 记住一件关于你的事：

```text
记住：我住在上海，习惯用中文回复
```

agent 会把它存成一条 markdown 笔记（`~/.kclaw/memory/notes/` 下的一个 `.md` 文件），并维护一份全文检索索引（SQLite FTS5——SQLite 的全文检索扩展，让关键词搜索更快）。

验证它跨会话生效：

1. `/clear` 开一个新会话。
2. 问：`我住哪？`

agent 每轮回复前都会先检索相关记忆，所以即使换了会话，它也应该知道你住在上海。想看、改、删某条记忆，直接编辑或删除对应的 `.md` 文件即可，kclaw 下次启动会自动同步。

## 6. 定时任务

让 kclaw 每天定时自己干活。先进入 WebUI（下一节），切到「任务」页，在表单里填三样：

- **name**：`早报`
- **cron**：`0 9 * * *`（cron：类 Unix 系统的定时表达式，五段依次是 分 时 日 月 周，这一行表示每天 9:00）
- **prompt**：`写一份今日早报：一句晨间提醒，加一条今天值得注意的事`

创建后，daemon 每 30 秒检查一次有没有到期的任务；到点自动开一个新会话（标题就是任务名）执行 prompt，执行结果记在这条任务上。同一页也能编辑任务、用行内开关停用或启用、删除任务。

终端里随时查看：

```bash
kclaw jobs list
```

输出一张五列表格：name / cron / enabled / nextRunAt（下次触发时间）/ lastStatus（上次执行结果）。

## 7. WebUI

```bash
kclaw web
```

这一条命令会：确认 daemon 在运行（不在就自动启动）→ 读取 `~/.kclaw/token`（daemon 的访问凭证）→ 拼出带登录信息的地址 → 调起系统浏览器打开。页面拿到 token 后存进浏览器本地存储并从地址栏清掉，之后再刷新不用重新登录；终端里打印的地址是去掉 token 的干净版本，可以放心复制。

界面是左侧会话栏加四个页面：

| 页面 | 用来做什么 |
|------|-----------|
| 对话 | 与 CLI 同款的流式对话和确认卡片；切到别的页面时对话不中断 |
| 任务 | 定时任务的增删改、启用开关、执行结果（上一节用的就是它） |
| 审计 | 查每次工具调用的允许/拒绝记录 |
| 回收站 | 被删除的会话，可恢复或彻底删除 |

左侧会话栏可以新建、重命名、删除会话。WebUI 与 CLI 功能对等，用哪个完全看习惯。

## 8. 数据在哪、怎么停止

全部数据都在 `~/.kclaw/` 一个目录里：

```text
~/.kclaw/
├── config.yaml      # 模型配置（向导写的就是它）
├── AGENTS.md        # agent 人设，会注入系统提示词
├── token            # 访问凭证
├── daemon.json      # daemon 运行信息（端口、pid）
├── sessions/        # 每个会话一个目录，messages.jsonl 是完整对话
├── memory/          # 记忆笔记 + 检索索引
├── jobs.db          # 定时任务
├── attachments/     # 附件
└── logs/            # 日志
```

备份或迁移 kclaw，复制这个目录就够了。daemon 是后台常驻进程；想停掉它：

```bash
kclaw daemon stop     # 停止 daemon
kclaw daemon status   # 查看状态（kclaw status 是同一命令的别名）
```

之后再 `kclaw chat` 或 `kclaw web`，它会自动重新启动。

遇到 `command not found: kclaw`、页面 401、端口对不上等问题，先查 [README](../README.zh-CN.md) 的「常见问题」表。

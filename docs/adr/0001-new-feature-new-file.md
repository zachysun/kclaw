# ADR-0001：新增功能 = 新建文件

状态：已接受（2026-09-04）

## 背景

项目希望向"约定式扩展"演进：新增工具、钩子、记忆写入/检索方式、压缩方式等，理想形态是不改核心代码、按规范新建文件即可。问题是从哪里开始、以什么抽象承载。

## 决策

把 **"新增功能 = 新建文件"** 列为项目演进的核心原则，并以**注册机制**（而非直接加载文件）作为承载该原则的核心抽象——代码文件只是注册来源的第一种实现，未来可以加配置注册、远程注册等，接口不变。

钩子系统是这一原则的第一个完整落地（见 [hooks](../core/hooks.md)），其四个关键决策：

1. **位置网格封闭枚举**：run/LLM/工具/轮次/压缩/思考/系统提示词的扩展点收敛为有限个命名位置（14 个），新增位置必须改核心——扩展的是位置上的逻辑，不是位置本身。协议封闭，扩展开放。
2. **HookChain 注册接口是唯一挂载入口**：内置钩子静态注册、用户钩子每 run 现扫动态注册，两种来源走同一个接口，调用方只见 `hooks: HookRunner`。
3. **用户钩子 fail-open**：用户钩子失败不伤主流程（跳过 + 发 hook.failed 事件可见），禁止声明 fatal；内置钩子保持迁移前的原语义。改写权只开放给明确设计过的位置。
4. **内置钩子放源码目录**：`core/hooks/builtin.ts` 随版本演进；`~/.kclaw/hooks/` 是用户扩展通道，一般不用。

## 后果

- 后续同类改造（工具、记忆、压缩的可插拔化）应复用同一模式：封闭枚举 + 注册接口 + 双来源装载 + 用户侧 fail-open。
- 内置逻辑迁入钩子后行为有少量可见变化（此前静默失败的内置逻辑现在发 hook.failed 事件），属于增强可见性而非语义破坏。
